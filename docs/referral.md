# 转诊协作边界与口径

罕见病门诊网络包含省级医院、地市医院和发起转诊的基层机构。本文件定义系统维护的业务事实、状态时限与监管口径；代码实现位于 `src/services/`。

## 1. 只追加的事实，可变的投影

- **版本链**：辖区人口、机构属性、门诊资质、可接诊病种、专科坐诊号源都以 `(主体, valid_from)` 版本链保存。调整人口或撤销能力只会插入新版本，旧版本与旧数值永不更新、不删除（数据库触发器强制）。"某时点的有效值" = `valid_from <= as_of` 的最新一条。
- **转诊事件流 `referral_events`**：接诊、补材、退回、会诊、转接、随访等每一步都是只追加事件，转诊内 `seq` 连续。`referrals` 表只是可由事件重建的投影。
- **审计 `access_audits`**：授权资料的每一次允许/拒绝读取都留痕；授权撤回后审计本身保留。
- **监管快照 `regulatory_snapshots`**：每次监管报告按 `as_of` 重算并只追加保存。人口或机构能力调整后，历史报告与历史时点的重算结果都不会被重写。

## 2. 授权分级

- `referral_summary`：去标识化转诊摘要的基础范围。
- `genetic_results`：遗传与基因检测资料的更严范围。授予该范围必须显式给出可读机构白名单；即使患者已授权，非白名单机构读取仍被拒绝。
- 授权有生效/失效时间，可撤回（只置 `revoked_at`，不删记录）。撤回立即阻止一切新读取（含接诊方），但依法保留历史业务事实与审计。
- 材料读取还要求机构是该转诊的参与方（发起机构、被指派/接诊机构、转接目标或事件责任人）。

## 3. 提交校验与重复识别

- 基层提交时按病种类别校验必要材料（`src/policy.js`）；基因类材料逐项走基因授权判定。校验失败的提交也记录 `submission_attempts(result='rejected')`。
- 幂等：同一 `idempotency_key` 返回原转诊；同机构相同负载识别为重复提交，不产生第二条转诊。
- 疑似重复患者按伪名、联系方式哈希、出生年/性别、辖区、表型重叠打分，仅提示不自动合并；疑似重复检查按"同一检查编码 + 日期窗口（默认 30 天）+ 疑似同一患者"提示。人工可在患者身份（伪名）级别给出 same/different 判定，抑制后续重复提示。

## 4. 候选机构是辅助，不是诊断

候选排序只返回**候选与理由**，最终接诊机构由医生选择，系统不代行诊断、不自动分诊。排序因子与权重（`src/policy.js`）：

| 因子 | 权重 | 说明 |
| --- | --- | --- |
| 病种能力 capability | 0.35 | designated 1.0 / specialty 0.75 / general 0.5 |
| 距离 distance | 0.25 | 1 − min(距离 km / 200, 1) |
| 候诊 waiting | 0.25 | 1 − min(候诊天数 / 30, 1)，候诊按号源与在途待办估算 |
| 紧急适配 urgency_fit | 0.15 | 能否在该紧急度接诊时限内安排 |

无有效资质、能力撤回、号源暂停的机构不进入候选，而在 `excluded` 中给出原因。每次生成的候选集固化为不可变快照，医生从该快照中选择；选择时再校验能力仍有效。

## 5. 状态机、责任人与时限（SLA）

每个事件都记录责任机构、操作人与处理时限；最近事件开启的待办（`open_phase/sla_due_at/assignee`）即当前未结责任。

| 待办环节 | 责任方 | 时限 |
| --- | --- | --- |
| triage 接诊/退回 | 被选机构 | urgent 4h / priority 12h / routine 24h |
| supplement 补交 | 发起基层机构 | 48h |
| supplement_review 复核 | 接诊机构 | 24h |
| mdt_schedule 会诊排期 | 召集机构 | 72h |
| mdt_feedback 会诊反馈 | 召集机构 | 排期后 48h |
| transfer 转接响应 | 目标机构 | urgent 8h / 其余 24h |
| follow_up 随访触达 | 接诊/发起机构 | 随访到期日 |

- **并发接诊互斥**：接诊采用条件 UPDATE（CAS），跨机构并发时仅一方成功，输家得到明确冲突错误；转接只能由目标机构接诊。
- 邀请/转接超时可由清扫接口幂等失效（超时后邀请释放、转接退回原持有人），并产生系统事件。
- 随访连续 3 次触达失败判定为失联（`lost_contact`），终结该转诊。

## 6. 监管口径（按当时有效版本）

监管接口均接受 `as_of` 参数：

- **覆盖缺口** `GET /v1/regulatory/coverage?as_of=...`：范围为省级医院与人口 ≥ 300 万的地市（人口取该时点有效版本）。区分"挂牌数"（有效资质）与"可达数"（有效资质 + 至少一项活跃病种能力 + 对应专科活跃号源），分别给出"未挂牌"与"已挂牌但不可达"缺口。
- **转诊积压与超时** `GET /v1/regulatory/backlog?as_of=...`：按事件重放得到当时未终结转诊，按环节汇总，并列出时限已过的明细（责任人、超期小时数）。
- **一致性核查** `GET /v1/regulatory/consistency`：校验投影状态与事件重放一致、事件序号连续、无未清扫超时邀请/转接、无绕过转接流程的并发接诊。服务重启后可直接运行验证。
